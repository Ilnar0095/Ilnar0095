# Шортсы «Необычной Кухни» — формат, съёмка, монтаж

Юнит для вертикальных коротких видео: **YouTube Shorts, Дзен-ролики, VK Клипы, TikTok** —
одна и та же раскадровка годится везде, меняется только описание и хештеги.

Здесь живут сценарии. Они двойного назначения: человек читает таблицу и идёт снимать,
а `dzen/tools/shorts.py` читает ту же таблицу и монтирует из ваших кадров готовый mp4.

```
dzen/shorts/
  002-kartofelnye-rozochki.md
  004-kurica-v-kofe.md
  005-syrniki-s-chesnokom.md
  006-mandariny-v-bekone.md
```

## Чем шортс отличается от ролика для Дзена

| | Дзен-ролик | Шортс |
|---|---|---|
| Решение смотреть | принимается 3–4 секундой | принимается **0–2 секундой** |
| Досматриваемость | 40–55 % — норма | 70 %+ норма, <50 % — ролик мёртв |
| Звук | часто выключают, но терпят | смотрят без звука **чаще**, субтитры обязательны |
| Финал | CTA на канал | **петля**: конец должен объяснять начало, тогда идёт второй прогон |
| Рецепт | в тексте статьи | в описании + закреплённом комментарии |
| Хронометраж | 45–90 сек | **18–45 сек**, длиннее 55 алгоритм режет |
| Отношение сторон | 16:9 или 1:1 | строго **9:16, 1080×1920** |

## Правила, за которыми следит чекер

`python3 dzen/tools/shorts.py check <имя>` — печатает то же, что я считаю при приёмке.

| Правило | Норма | Зачем |
|---|---|---|
| Длительность | 18–55 сек | >60 сек уже не шортс; <18 не успевает продать идею |
| Первый план | ≤3.0 сек и **готовое блюдо крупно** | 30 % уходят до третьей секунды |
| Число планов | 4–12 | меньше — статика, больше — мельтешение |
| Средний план | 2,8–6,5 сек | темп удержания |
| Реплика | ≤92 символов | две строки субтитра, третья лезет под кнопки интерфейса |
| Темп речи | ≤2,9 слова/сек | быстрее — не дочитывают без звука |
| Титр | ≤28 символов | читается за кадр, а не перечитывается |
| CTA | подписка + указатель «рецепт под видео» | иначе досмотр не конвертируется в переход |
| `loop:` в шапке | заполнен | петля = второй прогон = удержание выше |

## Формат сценария

Шапка (YAML) + таблица. Четвёртая колонка — титр на экране, она опциональна.

```markdown
---
number: 007
type: shorts
topic: Груша в слоёном тесте с сыром
duration: 38
size: 1080x1920
voice: ru-RU-SvetlanaNeural
loop: финал объясняет первый кадр, поэтому смотрят дважды
src: C:\\shots\\007
status: draft
---

# Шортс №007 — «Груша в тесте», 38 сек

| Тайм | Кадр | За кадром | Титр |
|---|---|---|---|
| 0–2.5 | Крупно: разрезанное тесто, тянущийся сыр | В ресторане это 900 рублей | 900 ₽ |
| … | … | … | … |
```

Тайминги можно писать `0–4`, `4-12`, `0:12–0:24`. Пустой конец (`| 34 |`) = план на
3 секунды. Если порядок планов нарушен, инструмент растянет их сам.

## Съёмка на телефон (что реально нужно)

1. **Один кадр-доказательство.** Не «красиво», а «видно трюк»: слайс у линейки, тянущийся
   сыр, хруст на зубах, карамельный блеск.
2. **Один кадр-провал.** Что происходит при ошибке: развалившаяся розочка, пригоревший
   кофе. Это поднимает комментарии сильнее любого рецепта.
3. **Звук отдельно.** Шипение и хруст пишем вторым дублем ближе к микрофону, потом
   кладём под видео — удержание на звуке выше, чем на музыке.
4. Свет от окна сбоку, телефон на уровне еды (30–45°), не сверху. Никаких ламп под
   потолком: они убивают глянец, а глянцевое блюдо и продаёт.
5. Каждый план — 4–6 секунд движения: рука, ложка, пар. Статичный кадр длиннее
   6 секунд листают.

## Монтаж

Нужны `ffmpeg` и (для озвучки) `edge-tts`. Дальше одна команда:

```bash
python3 dzen/tools/shorts.py plan   004-kurica-v-kofe --src C:\\shots\\004   # что нашлось из кадров
python3 dzen/tools/shorts.py subs   004-kurica-v-kofe                        # .srt + .ass
python3 dzen/tools/shorts.py render  004-kurica-v-kofe --src C:\\shots\\004  # готовый mp4
```

Что делает `render`:

* подбирает файлы к планам (по имени файла в описании кадра, иначе — по порядку);
* озвучивает каждую реплику `edge-tts` и **пересчитает тайминги под длину голоса** —
  так закадр не обрывается и не спешит;
* нарезает кадры под 1080×1920 с лёгким наездом (Ken Burns), вжигает субтитры из `.ass`
  с отступом снизу 470 px, чтобы текст не залез под кнопки и описание;
* титры ставит сверху, в свободной зоне;
* склеивает сегменты без перекодирования и складывает всё в `dzen/tools/.work/<имя>/`.

Флаги: `--no-voice` (без голоса, только субтитры), `--static` (без наезда), `--fps 25`,
`--out <папка>`, `--report` (отчёт по правилам после сборки).

## Загрузка в YouTube

* Название — до 60 символов, с числом: «Мясо в кофе. Так можно? #shorts».
* Описание: 2 строки + список ингредиентов + ссылка на статью канала. Рецепт — туда же.
* **Закреплённый комментарий**: «Полный рецепт и цена порции — в описании» + тег.
* Обложка — 9:16, тот же первый кадр, подпись крупно.
* Музыку берём из YouTube Audio Library: чужая дорожка = страйк по правам и ролика нет.

## Метрики, которые смотрим через сутки

| Метрика | Где | Норма |
|---|---|---|
| Доля просмотров из ленты («swipe» — ушли сразу) | YouTube Studio → Охват | уйти должно <35 % |
| Средний % просмотра | там же | ≥70 % для ≤40 сек |
| Просмотры с петлёй | «повторные» | ≥15 % — петля работает |
| Переходы в описание / на канал | трафик | 1 %+ от показов |

Плохой показатель «ушли сразу» = виноват **первый кадр**, а не текст. Менять надо съёмку,
не сценарий.

## Чего этот инструмент не делает

* Не генерирует видео нейросетью — кадры должны быть свои (телефон — достаточный
  источник). ИИ-видеомодель подключается через `bot/.env` (`VIDEO_PROVIDER=replicate`),
  и тогда ролик-тизер можно попросить у бота.
* Не делает музыкальный монтаж и не ищет права на треки.
* Не выкладывает: публикация остаётся вашим ручным действием.
